Scene graphs that store evidence, not decisions.

OpenBelief-Nav is a training-free open-vocabulary scene graph for language-guided robot navigation. Each object node preserves its multi-view phrases, reliability weights, and exact provenance instead of a single committed label — so segmentation, retrieval, unsupported-query rejection, and execution-time correction all become task-time readouts over one frozen graph.

The problem

Maps that make up their mind too early can't take it back

A sofa seen from four viewpoints may be proposed as sofa, chair, bench, or armchair — occlusion, scale, and foundation-model noise guarantee disagreement. ConceptGraphs, HOV-SG, FSR-VLN, and DualMap all resolve that disagreement at construction time, exposing each object as one fused feature, label, or consensus state. Three things go wrong.

Commitment destroys evidence

When a majority vote picks one label, the minority phrases are gone. Yet among nodes misclassified by majority vote, the correct category is often still present in the stored phrase set — information the system already paid to acquire, discarded by how it is stored.

store observations, not verdicts

No single readout fits every task

The readout that maximizes benchmark segmentation is not the one that maximizes navigation success — our experiments show posterior projection wins segmentation while a consensus readout wins retrieval. A map that commits to either loses the other.

choose the readout per task

Similarity always returns something

Cosine similarity has an argmax even when the queried object does not exist or the best match is stale. A post-hoc verifier can't recover a target that was never in its candidate set — rejection must be calibrated at retrieval time.

support testing, not just ranking
Method

Four stages, each pushing commitment later

An object node stores the evidence-preserving state 𝓑ᵢ = (Pᵢ, fᵢᵛ, 𝓞ᵢ, 𝐕ᵢ, 𝐩ᵢ, fᵢᵗ, ρᵢ) — point cloud, aggregate visual feature, the raw language observations, concept-level evidence with its smoothed belief, a consensus text feature, and a trust status. The visual and language channels are never destructively fused during mapping; every cross-modal decision is deferred to a readout.

STAGE 1

Evidence acquisition

A frozen VLM proposes phrases; a promptable segmenter grounds each phrase as masks. Every mask is kept as an observation with its phrase, confidence, 3D support, and exact frame + mask identity.

oe = (te, je, ℓe, ce, ne)
STAGE 2

Geometric–visual association

Observations merge on 3D overlap, with visual similarity only as a rejection cue — never on predicted names. Precision is favored: a false merge is irreversible, a missed one is recoverable at query time.

e ∼ e′ ⇔ Ωr ≥ τg ∧ ⟨feᵛ, fe′ᵛ⟩ ≥ τv
STAGE 3

Belief construction

Observations are weighted by what we actually know — segmentation confidence and 3D support — grouped into synonym-aware concepts, and Dirichlet-smoothed so sparse evidence can't fake certainty.

we = ce√n̄e  ·  pik = (Vik+α) / (ΣVij+αKi)
STAGE 4

Task-time readouts

Vocabulary projection, free-form retrieval, and support testing are separate operators over the same frozen evidence — and at deployment, arrival observations physically test the selected hypothesis.

readout(𝓑ᵢ, task) — graph never rewritten
The full pipeline. Posed RGB-D observations produce per-observation visual, linguistic, geometric, reliability, and provenance evidence. Geometric–visual association forms object nodes without any hard name-equality merge. The preserved evidence supports vocabulary projection, free-form retrieval, unsupported-query rejection, and query-preserving correction after physical verification.

One graph, many answers

“What is this object?” depends on who's asking

Because a node stores evidence rather than a decision, the same frozen graph answers differently — and correctly — for each task.

Vocabulary projection

The benchmark vocabulary arrives only at evaluation time. The stored belief is refined by the visual feature within its existing support, then projected onto the target classes — secondary hypotheses an early top-1 would have discarded remain recoverable.

ŷᵢ(c) = (1−λ)Σ p̃ikWikc + λ·softmax⟨fᵢᵛ, tc⟩

Free-form retrieval

Query similarity fuses the visual and text heads — but the fusion weight is per-node, conditioned on the trust status the belief construction produced:

no language evidence (K=0) trust vision only λ = 1.0
degraded belief lean visual λ = 0.7
trusted belief trust the text head λ = 0.2
Sᵢ(q) = λᵢ⟨fᵢᵛ, f_q⟩ + (1−λᵢ)⟨fᵢᵗ, f_q⟩

Support test → abstention

Retrieval only returns a target when its score clears a support threshold; otherwise it abstains. An absent or unsupported query is refused at retrieval time — before the robot drives anywhere — instead of being “verified” after the fact.

retrieve(q) = argmax Sᵢ(q) if max ≥ τs, else ABSTAIN

Deployment

Navigation is a physical test of the hypothesis

A retrieval result is a hypothesis, not a fact. On arrival, the robot's RGB-D observation runs an ordered verifier — re-observe if the candidate isn't sufficiently visible (absence of view is not evidence of absence), reject on semantic mismatch or on a semantic match that fails to coincide geometrically with the stored node, confirm otherwise. Rejection changes exactly one thing: a per-query exclusion set. The graph is never modified and the query is never rewritten.

Real world

Deployed on a Unitree G1 humanoid

Compute-heavy semantic reasoning runs offboard; an onboard Jetson keeps the motion loop local. The bridge is Zenoh. The robot navigates to a candidate, looks, and lets physics vote.

CORRECT

Valid mapped candidate

The verifier must confirm without a false rejection — correction should cost nothing when the map is right.

CONFUSABLE

Same-category distractor

A look-alike outranks the true target. Arrival evidence rejects it; the query re-grounds to the supported alternative.

REMOVED

Object gone after mapping

Correct behavior is rejection followed by abstention — the honest answer when no supported candidate remains.

STALE DUPLICATE

Outdated duplicate hypothesis

The map holds an old copy of a moved object. Rejection is scoped to the query; the persistent graph is untouched.

Execution-grounded correction on the humanoid. Top: a confusable candidate is rejected on arrival and the original query re-grounds to a supported alternative, which is confirmed. Bottom: a removed target's stale candidate is rejected and the system abstains — no supported candidate remains. In both cases the persistent graph and the instruction are unchanged.
